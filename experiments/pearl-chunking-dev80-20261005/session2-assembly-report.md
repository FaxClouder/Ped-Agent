# Session 2 assembly and source support report

*Experiment-local implementation and fixed-source checks · status: current · 2026-10-05*

Implemented `assemble.py`, `support.py`, `review.py`, `score.py`, and `test_assembly_support.py`; historical modules and artifacts are unchanged. Assembly accepts JSON source chunks, source views and the common parent graph. P0 retains source core/overlap only, P1 recovers same-section neighboring original paragraphs without crossing tables, and P2 uses all intersecting public parents and refuses a graph that does not cover the core. Prefix metadata never enters visible evidence.

The main panel takes up to 100 ranked seeds; the diagnostic panel takes up to 10. Source-coordinate subtraction removes repeated same-document, same-version intervals across ranked seeds while retaining identical text from different documents. Records contain raw, expanded, deduplicated and final snapshots, full source headers, final Unicode offsets, hashes, actual serialized token counts, budget-stop records and elapsed assembly time.

The truncator consults tokenizer offsets (`encode_with_offsets` for the actual BGE counter) and searches source Unicode prefix boundaries in descending order, counting the entire serialized candidate at each step. It therefore finds the maximal legal source prefix even when BPE counts or offset-digit header lengths are nonmonotonic; it does not assume character-count binary search is valid. Synthetic separator endpoints are excluded and later ranked seeds stop after the first overflow. This correctness-first exhaustive search may have material assembly latency and is recorded separately from retrieval latency.

Source support is an offline map independent of old chunk identifiers. Unique anchor matching only emits location candidates. It never inherits an affirmative semantic label. TRUE requires reviewer provenance, semantic rationale and full coverage of every reviewed necessary source span; partial coverage or a different source version yields unknown. Three-valued AND/OR directly reuses the frozen Layer 2 `score_support` function. Failed cells retain their denominator.

Saved in `outputs/pearl-chunking-dev80-20261005-03/`: `common-support-map-r01.json` has all 80 intent requirements and groups, with 8 fixed-sample intents source-reviewed and 72 pending. `source-review-packets-r01.json` and `source-reviews-r01.json` hold 8 actual canonical source packets and semantic rationale records. The reviewer read original source text; no method, retrieval rank, old score or old support label informed the review. Provenance explicitly records author-agent source review, `independent_review=false` and `human_verified=false`; independent review remains the root coordinator's separate task.

Reviewed necessary spans conservatively retain complete original paragraphs. This deliberately yields unknown if only a partial paragraph is visible; it can understate sufficient shorter excerpts and must not be interpreted as a negative semantic label. The map is one shared version for every configuration. For dev012 it preserves both detailed exception fractions and the generalized mechanism. The numeric strata sample happens to have numerical support in prose; these two reviewed source packets do not validate table-cell retrieval or table semantic support.
