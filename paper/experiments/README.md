# 实验与测试结果记录规范

## 一次运行的最小闭环

1. 将实验参数保存到 `configs/`，在正式测试前冻结基线、指标和阈值。
2. 用 `scripts/new_run.ps1` 创建唯一 `run_id`。
3. 在 `metadata.yaml` 中记录 Git 提交、数据版本、依赖环境和完整命令。
4. 将结构化指标写入 `metrics.csv`，把异常、失败样本和解释边界写入 `notes.md`。
5. 汇总脚本只读取已完成的 run，不手工覆盖原始指标。
6. 论文中的每个数值、表格和图都应能回溯到一个或多个 `run_id`。

## 推荐目录

```text
experiments/
├── configs/                 # YAML / JSON 配置
├── data/
│   ├── raw/                 # 本地原始数据，默认不提交
│   └── processed/           # 可复现的小型处理结果
├── results/
│   ├── runs/<run_id>/       # 单次运行不可变记录
│   └── summary/             # 跨运行汇总 CSV / JSON
├── figures/                 # 由结果生成的图
└── templates/               # 标准记录模板
```

## 结果边界

- 单元测试、集成测试和构建通过证明工程实现满足当前测试契约，不等于科研有效性成立。
- 真实服务连通只证明依赖可用，不等于回答质量或分析精度达到论文标准。
- 论文结果应说明样本、基线、统计方法、失败样本和适用范围。
- 未完成、被中断或配置漂移的运行仍保留，但在 `metadata.yaml` 中标记状态，不能进入正式汇总。
