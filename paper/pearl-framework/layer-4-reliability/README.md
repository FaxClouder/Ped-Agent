# Layer 4 · Reliability

*拒答与可靠性评价 · status: 待设计 · 2026-09-28*

> **编号**：本目录是 PEARL Layer 4 的 **Reliability 部分**，原为独立的 Layer 4。Layer 4 的另一部分 Grounding 在 [layer-3-grounding/](../layer-3-grounding/)。目录名未改，编号含义已变。合并理由见 [PEARL-framework.md](../PEARL-framework.md) §8.4，两部分分工见 §2.4。

本部分评价系统在证据不足时是否正确拒答，以及是否因过度保守而在证据充分时也拒答。评价的失败模式是**该拒答却给出确定性结论**。

**与 Grounding 部分的关系**：两者合并为 Layer 4，回答同一问题的两面——答案是否只说证据支持的内容。**合并编号不等于混算**：两部分指标分别汇总、主表分别出现，不构造合成分数。

## 职责边界

| 项目 | 归属 |
| --- | --- |
| 应拒答题上是否拒答 | 本部分 |
| 可回答题上是否误拒 | 本部分 |
| 拒答理由是否成立 | 本部分 |
| 作答时的答案正确性 | Layer 3 |
| 作答时的证据支持 | Layer 4 · Grounding |

## 待定义指标

来自 [framework.md](../framework.md) §3：

| 指标 | 原始口径 |
| --- | --- |
| Abstention F1 | 将"应拒答"设为正类，报告拒答 Precision/Recall/F1 |
| False Answer Rate | 应拒答问题中仍给出确定性结论的题数 / 应拒答题数 |

**防一律拒答**：须同时报告可回答题上的正确率。只报 Abstention F1 会让"全部拒答"策略看起来表现良好。

## 四象限报告

[framework.md](../framework.md) §5 要求区分四种结果，本层是该划分的核心：

| | 应作答 | 应拒答 |
| --- | --- | --- |
| **系统作答** | 正确回答 / 有证据但答错 | 证据不足却编造（False Answer） |
| **系统拒答** | 错误拒答 | 正确拒答 |

四象限计数须与 Layer 3 的正确性结果联合报告，不单独呈现 Abstention F1。

## 设计时须解决的问题

1. **拒答题的数据来源**：Stage 2 的 `build_dev_scope.py` 明确不包含 20 个拒答 intent。这些 intent 的标注状态、可用性和"为何证据不足"的说明须先确认。没有拒答子集，本部分无法评测——这也是当前与 Grounding 合并为一层的现实理由之一。

2. **"确定性结论"的判定**：False Answer Rate 的分子需要判定答案是否构成确定性结论。带限定语的部分回答（"可能约为 0.6 m，但原文未明确"）属拒答还是作答，须预先定义。

3. **拒答理由的评价**：正确拒答但理由错误（说缺少 A 证据，实际缺少 B 证据）是否算成功，须明确。

4. **与 Layer 1.5 的关系**：系统的拒答决策通常基于充分性判断。Layer 1.5 的 Sufficiency Accuracy 度量判断准确性，本层度量判断转化为行为的结果。两层指标须能交叉验证——充分性判断正确但仍误拒，属本层的决策阈值问题。

5. **条件性不可回答**：行人交通领域常见"在某条件下无数据"。这类题是完全不可回答，还是可部分回答并声明限制，须在题型体系中区分。
