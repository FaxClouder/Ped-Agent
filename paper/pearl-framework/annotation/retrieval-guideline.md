# Layer 1 Retrieval 标注操作规范

*英文原文与来源锚定证据组的试标规则 · status: plan · 2026-09-29*

本规范执行 [指标协议](../layer-1-retrieval/metrics.md) 的 requirement／atom／bundle／group 语义。先在 [固定语料](../datasets/retrieval-corpus/README.md) 上制作开发题试标，再决定全量标注是否可行。旧题集、旧 Gold 和旧检索结果不作为新标注输入。

## 一、出题与资格

1. 仅从固定语料原文提出可回答的英文问题；每个 intent 只有一个本轮主 query，记录独立 `intent_id` 和 `family_id`。题目必须点明限制答案范围的研究、对象、场景和条件。若所问答案并未由当前语料共同支持，标记为候选问题并移出本轮 Q⁺，不能创造空 Gold。
2. 四个互斥主层按跨论文必要性 → 数值／表格 → 单篇多证据 → 单来源事实／机制判定。数字只作为研究身份或背景、不属于回答目标时，不自动划入数值层。交叉标签保留表格、条件、跨页、替代支持等属性。
3. 参考答案用完整而有限的 claim 写出；不能把论文不同实验条件下的数值、参与者或研究结论拼成一项答案。跨论文题在 query 中指明要比较的研究与角度，答案保留每篇各自的条件。
4. 出题阶段不看旧 Gold、检索排名或评分；同一题族与近重复问法不能跨开发／评估集。试标题先列入开发候选；通过子 Agent 复核后可计入初步开发集，并保留 `agent_reviewed_preliminary` 质量状态。

## 二、证据标注

| 对象 | 操作规则 |
| --- | --- |
| source atom | 记录语料 `source_id`、PDF 页序（从 1 开始）、表格编号与行／列／单元格或可定位的原文短语、原文实际支持的事实、对象和条件。source ID 在 manifest 中解析为 SHA-256；不可只凭页码判断支持 |
| requirement | 一项不可再拆的必要答案事实；记录研究身份、场景、单位、条件、比较角色。数值与单位、表头或条件若分布在多处，用同一 requirement 的多个 atom 表达 |
| support bundle | 一条完整支持 requirement 的非空 atom 集，内部 AND。只有来源和条件均等价时才增加替代 bundle，bundle 之间 OR；不能仅因字面相似就互换 |
| evidence group | 一条足以支持完整参考答案的非空 requirement 集，内部 AND。只有另一组能独立完成整个答案时才增加替代 group，组间 OR；跨论文题所需的不同论文必须在同一组中共同出现 |

一段原文能支持多个 requirement，但每一项都要独立说明它如何满足条件；多个 PDF 页／未来多个 child 可以共同支持一个 requirement。去除重复或逻辑冗余的严格超集组。源原子不得写死 chunk ID；新解析或切块后的 child 支持映射在排名密封后另做盲化核验。

`text_anchor` 需在指定 PDF 页经 Unicode 空白归一化后找到，保存足以回看原文的短语。`table_cell` 需保存表编号、行标签、列标题与单元格原值，并视觉核对对应关系；仅从提取文本中出现相同数字不足以证明表格映射。图中读数、估计量和带 ± 的统计量按原文精度与单位保留，不擅自解释 ± 的统计意义。

## 三、两阶段复核与争议

**阶段 A：子 Agent 语义复核（初步运行前）。** 初标 Agent 逐题核对原 PDF、答案范围、主层、每项 requirement 的必要性、各 bundle 的充分性及完整组。另一子 Agent 在不参考初标解释以外旧 Gold／排名的前提下重看原文和表格，指出错误、缺少的限制及可能的等价支持。争议记录提议、证据页、双方判定和另一子 Agent 的仲裁结论；未解决的题标为 `disputed`，不进入本次可计分 Q⁺，并报告数量与原因。试标 8 题全部安排子 Agent 复核；通过后可冻结初步 Gold-core 版本用于流程测试，状态标为 `agent_reviewed_preliminary`，不称人工 Gold。

**阶段 B：输出支持复核（排名密封后）。** 收集所有已执行方法的候选池，去除方法名、分数和排名信息。对冻结的 requirement／group 统一判断返回的实际 child 文本是否支持来源原子及其限制，记录支持、否定或未决及理由。相同 child 与同一要求的判定对所有方法共用；不能让某一方法的检索表现决定 Gold 修改。已有要求的等价支持可统一增补；答案范围或组结构变化需要 Gold 新版并重算所有方法。

当前目标是先跑通解析→检索→支持核验→评分→报告流程，取得明确标注质量的初步结果。现有 [质量分级](README.md) 的人工审查级别不作为这一阶段的运行门槛；所有当前语义与输出支持复核由子 Agent 承担，逐次记录执行身份、模型／提示版本（如可得）、审查范围、分歧和处理依据。8 题试标只报告逐项意见，不用小样本一致率宣称正式数据质量。

人工审查安排在流程与初步结果确认后，用于检查难例和改进开发集标注／实验配置。若改动语义 Gold，创建新版并对所有方法重算；调参只使用开发集。独立评估集若已揭示结果或接受基于结果的人工修订，其分析须标为探索性，之后需要新的封存评估集才能主张未见测试泛化。

## 四、试标验收

试标必须覆盖四个主层各 2 题，并至少包含表格单元格、原文不同页的证据、多篇论文共同支持、同一 requirement 的替代 bundle。机器检查来源 ID／哈希、PDF 页与锚点、非空组、引用关系、同题要求唯一性和互斥题型；子 Agent 复核再判断语义与表格。结构和锚点检查通过本身不表示答案充分。初步计分须完成阶段 A 的子 Agent 复核及必要仲裁，并冻结该次使用的 Gold-core 哈希；后续人工审查另存版本。
