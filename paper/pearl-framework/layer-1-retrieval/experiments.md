# PEARL Retrieval 实验协议

*英文单语四方法对照、数据构建与复现要求 · status: plan · protocol: retrieval-v0.2 · 2026-09-29*

本协议替代旧 E1–E5、旧题集及旧索引方案。指标见 [metrics.md](metrics.md)，统计见 [statistical-methods.md](statistical-methods.md)。以下数值为本次设计选择；[106 篇 Adobe-only 语料](../datasets/retrieval-corpus/README.md)已固定，[8 题 R1–R4 开发初步对照](../../../experiments/pearl-index-106-adobe-20260929/README.md#8-题-adobe-only-开发对照)已运行并完成盲化支持核验。R4 为冻结 R3 Top-100 的独立补跑；[80 开发／200 封存评估题集](../../../experiments/pearl-dataset-80-200-20261003/README.md)已于 2026-10-03 构建，完整题集运行及正式评估尚未完成。旧 108 篇 PyMuPDF 的[单组 R1 试标](../datasets/retrieval-pilot/preliminary-r1-2026-09-29.md)只保留为历史流程记录。

## 1. 研究对象与样本

新建 80 个开发 intent 和 200 个独立评估 intent，每个 intent 一个英文主查询。所有方法使用完全相同的 query 文本、可检索英文语料和语义 Gold。独立评估集在方法配置冻结后运行，不参与模型、参数、提示或阈值选择。

| 主要题型 | 开发目标 | 评估目标 | 证据要求 |
| --- | ---: | ---: | --- |
| 单来源事实／机制 | 20 | 50 | 同一来源即可构成完整组；保留必要条件 |
| 数值／表格 | 20 | 50 | 数值、单位、对象、条件及所需表头必须一起支持 |
| 单篇多证据综合 | 20 | 50 | 同一论文内至少两项必要证据；需要组合才能完成回答 |
| 跨论文比较／条件／冲突 | 20 | 50 | 每条完整路径都需要多篇论文；各方证据在同一组内共同满足 |
| 合计 | 80 | 200 | 均为语料可回答的检索问题 |

主分层互斥：先判跨论文必要性，再判数值／表格，再判单篇多证据，其余进入单来源事实／机制。表格、条件、冲突、等价来源、替代完整组、摘要／正文／跨页位置另外打标签，可重叠。开发／评估分别力争包含至少 16/40 个具有经核验替代完整组的 intent；若真实语料不足，应在运行前记录实际分布和协议修订，不能为凑配额制造等价证据。

**运行前实际分布登记（2026-10-03）**：80／200 已冻结／封存，四层配额达成。当前经核验替代完整组分别为 0／0，16／40 期望目标未达；具有替代支持 bundle 的 intent 为 8／19，两者不能混算。本轮不报告替代完整组题型的实测效果；一般 AND／OR 评分逻辑保留，不制造组，也不声称已穷举语料中所有等价路径。具体分布、复核和限制见 [题集冻结记录](../../../experiments/pearl-dataset-80-200-20261003/README.md#内容分布与运行前协议登记)。

同一 intent、近重复问法和仅替换数值的模板家族不能跨集。来源可以在两集共用，因此结论是固定语料上的新问题泛化，不是未见文献泛化；记录来源重用并做相关性敏感性分析。各题型不足目标时先修订计划，不能运行后按得分删题补题。

语料不可回答题不进入本轮 CEGR 分母，可留作后续拒答实验；不得把空 Gold 当完整命中。可回答题在解析／索引中丢失证据仍保留并计为检索未命中。

## 2. 四方法主矩阵

| ID | 配置 | 候选与最终排名 | 角色 |
| --- | --- | --- | --- |
| R1 | BM25 | 同一 child 库的前 100 项 | 词法基线 |
| R2 | BAAI/bge-m3 的 dense 通道，归一化向量余弦相似度 | 前 100 项；不启用其 sparse／multi-vector 通道 | 稠密基线 |
| R3 | R1＋R2 的 RRF | 两份前 100 列表按 chunk ID 合并，最多 200 候选，融合后取前 100 | 混合检索 |
| R4 | R3＋BAAI/bge-reranker-v2-m3 | 仅对 R3 的同一前 100 候选重排，保留完整重排排名 | 重排处理 |

两个模型名称是本轮候选配置，不是 PEARL 的依赖。未下载、未运行不写“可用”或“已验证”。若 R4 的运行资产无法准备，报告“未执行”，不能按前三组得分决定是否增加 R4，也不能换模型后沿用旧配置标识。

R3 的前 100 与 R4 的输入／完整输出必须含相同的候选 ID 和返回文本，仅顺序变化。因此在支持映射相同且该深度核验完成时，两者 CEGR@100 与 BestGroupCov@100 必须相等；若不等，先排查过滤、文本变动、缺项或日志错误，不能解释为重排改变候选证据总量。

固定比较为 R2−R1、R3−R2、R4−R3。R3−R1 另报描述性差值；不根据评估结果选择 `max(R1,R2)` 作为对照。R3 相比单通道增加候选来源和计算量，方法质量与成本一同报告；这是同一输出预算下的系统配置比较，不宣称等计算量比较。

## 3. 参数与控制变量

| 项目 | 本轮设置 |
| --- | --- |
| 主截断 K | 10 |
| 补充截断 | 1、5、20；均取同一最终排名前缀，不另行调参运行 |
| 诊断保存深度 D | 100；不足 100 时保存全部结果及真实数量 |
| BM25 | k1=1.2、b=0.75；记录实现和 IDF 公式，不用不同实现的同名分数冒充一致 |
| 英文词法处理 | query 与 child 同一分析器：Unicode NFKC、小写、连续英文字母或数字作为 token；无停用词删除、无词干化；保存版本与固定样例 |
| RRF | k=60，等权；只使用排名，见下式 |
| 排名并列 | 同阶段分数相同时按 chunk ID 字典序；稳定规则写入 manifest |
| dense | 固定 query／document 编码配置；记录 revision、归一化、检索方式及索引参数 |
| reranker | 固定 revision 和输入处理；保存实际送入模型的 query／child 文本及截断标记 |
| 随机性 | 数据划分和统计 seed=20260929；随机算法另存种子与重复运行，不能把重复运行当新 intent |

RRF 对 union 中的候选 c 定义：

$$
\mathrm{RRF}(c)=\sum_{m\in\{R1,R2\}:c\in L_m^{100}}\frac{1}{60+\mathrm{rank}_m(c)}.
$$

缺席通道贡献 0；排名从 1 开始。同一 chunk ID 在通道合并时去重，但语义重复且 ID 不同的 chunk 保留。此处候选合并是方法步骤，评分器不再额外去重或补位。k=60 是预先选定的实验值，不是普遍最优值。

共享的语料、解析器、child 构建规则和检索资格清单由新 `asset_manifest` 固定。解析器及切块的具体版本必须在开发运行前登记；它们是待实际构建的实验资产，不能从旧索引自动继承，也不能在四组之间不同。各组共用相同 child 文本，记录长度分布与检索 token 数。若模型发生截断，记下其输入视图；Layer 1 按实际返回的 child 文本评分，不能暗用 parent 内容。

首轮不对上述检索参数做搜索。任何模型／分析器／参数替换须在独立评估前完成，并产生新配置版本；变动后所有受影响的开发运行重新执行。

## 4. 新资产与冻结清单

下列名称是正式对照的逻辑文件。[80 题开发运行](../../../experiments/pearl-retrieval-dev80-20261003/README.md)已交付对应运行／方法记录、实际 child 盲审映射、统一评分与开发统计；200 题正式独立评估的运行资产尚未产生。路径由各次 run／delivery manifest 指定；输出使用独立目录，禁止覆盖现存结果。

| 逻辑文件 | 最小内容 | 冻结时点 |
| --- | --- | --- |
| `corpus_manifest` | 文档 ID、来源、英文筛选、源文件 SHA-256、可用范围 | 出题与构建前 |
| `query_gold_core` | split、intent／family ID、英文 query、参考答案、组／证据／条件、来源锚点、标注 provenance | 评估运行前 |
| `asset_manifest` | 解析器和配置、canonical 输出哈希、chunk 规则／tokenizer、全部 child 文本哈希、索引资格与构建哈希 | 对应配置首次运行前 |
| `method_manifest` | R1–R4 参数、代码版本、模型 revision 与权重哈希、依赖、设备、随机种子、输入截断规则 | 评估运行前 |
| `support_mapping` | Gold 来源片段到实际 child 的支持关系／组合、接受或拒绝理由、核验方式与版本 | 排名密封后，汇总评分前 |
| `run_manifest` | 协议／数据／配置哈希、run ID、时间、状态、缺失与重试记录、所有输出路径和哈希 | 每次运行保存 |

语义 Gold 和方法配置先冻结，评估排名密封。支持核验是预先声明的盲化评分环节：池化所有已执行组的前 100 child 和参考来源映射，去除方法名、分数与排名线索后核验。核验可由 Agent 辅助，但记录实际来源和质控，不能自动写为人工 Gold。

本轮实施先用经子 Agent 复核的小批开发题验证完整链路并发布标注为**初步／开发集**的结果，再扩展 80 题和封存 200 题。此阶段不以人工审查作为运行门槛。人工审查放在初步结果和流程确认之后，用于开发集难例与配置调优；若人工改动语义 Gold，应创建新版本并对各方法一致重算。已查看独立评估结果后据此调参的分析须标为探索性，不能仍称原封存评估上的未见测试结果。

所有方法共享同一支持映射。对每个 intent 检查单片段及可联合支持事实／条件的片段组合；不能仅用逐 chunk 独立相关性分数替代组合判断。主报告要求前 20 的支持判断无未决项；深度 21–100 如有未决项，该范围的完成排名／失败归因必须标为未决。不得把未标注直接判为无支持。

等价支持扩充仅用于已经冻结的证据要求。若发现组结构或参考答案错误，应保留原版本并统一修订／重算各组；不得只修正一个方法的分数，也不得用测试反馈重调检索配置。报告明确标记修订分析与原先冻结的主分析。

## 5. 必须保存的运行记录

| 记录 | 必填字段／内容 | 用途 |
| --- | --- | --- |
| 查询级 | run／intent／query／config ID、开始结束时间、状态、错误与重试 | 发现缺失，区分执行失败与检索漏失 |
| 稀疏与稠密候选 | 每通道前 100 的 rank、chunk ID、score、实际文本或不可变文本引用 | 核验来源与候选生成 |
| RRF union | 两通道排名、缺席标志、融合分数、最多 200 项的顺序与前 100 截断标志 | 分辨候选截断与排序 |
| 重排输入与输出 | 同一 100 个 ID、原排名／新排名、分数、模型输入文本／截断标记 | 定位重排收益或损失 |
| 最终排名 | 前 100 child、来源版本、页与原文锚点、parent ID、文本哈希 | 从一份排名计算所有 K |
| 评分明细 | 支持到哪一证据／组、组合判断、逐组覆盖、完整标志、首次完成排名、mapping version | 从原文复核每个指标 |
| 代价 | 各阶段 wall time、query 编码／检索／融合／重排成本、返回 token 数、设备 | 质量–成本报告 |

只保存 Top-10 不满足本协议。未在前 100 出现只说明该保存范围内未观测到，不能声称其真实全库排名大于 100、来源不存在或索引没有它；这些结论各自需要额外核验。

## 7. 实验准备优先级与验收

*准备状态核对日期：2026-10-03；依据 PEARL 文档及已核验实验输出。表列依赖次序，实际完成项见 §7.3。*

### 7.1 正式独立评估前

| 顺序 | 工作 | 已有基础 | 需要交付与验收 |
| --- | --- | --- | --- |
| P0-1 | 确定并冻结英文领域语料 | 英文范围、来源版本规则 | 新 `corpus_manifest`：来源 ID、实际路径、语言、SHA-256、纳入／排除依据和规模；检查原文可读、表格可核验，以及四类问题的证据是否足够。原始论文可经重新选取和核验纳入，旧题集／标签／索引／结果不得继承 |
| P0-2 | 落实标注操作规则并试标 | requirement、atom、bundle、group 的字段与逻辑 | 明确标注者或 Agent 配置、复核范围、一致性检查对象与抽样、争议仲裁、等价支持接受条件；从新开发集先制作覆盖四类题的小批样本，逐题核对原文、条件和完整组。试标属于 80 个开发 intent，不读取或挪用评估题调试 |

| P1-4 | 构建统一解析、child 与索引 | 四方法共享输入的设计 | 实际选择解析器、切块规则和 tokenizer；新建 canonical、child 库及索引，填写 `asset_manifest`。抽查表格、跨页和多片段证据的保留情况，记录缺失；原文有证据而处理丢失的题仍保留在评分分母 |
| P1-5 | 固定四方法并打通运行记录 | R1–R4 参数、候选与排序规则 | 完整 `method_manifest`、真实模型 revision／权重哈希、依赖与设备记录；用开发题确认模型可执行，保存通道排名、融合 union、重排输入输出、最终 Top-100、文本哈希、耗时、错误与重试。运行错误与合法空结果分开 |
| P1-6 | 实现支持映射校验、评分和统计 | 指标公式、固定算例、预设统计 | 实现 Gold／mapping／日志验证和逐题评分；核验 AND/OR、联合 child、替代组、条件不符、重复占位、空 Gold 拒绝及未决状态；核验 R3/R4 同候选全深度覆盖不变。统计输出含配对差、CI、McNemar＋Holm，并能追溯至逐题记录 |
| P2-7 | 开发集完整演练并冻结发布版本 | 开发／评估隔离、冻结时点 | 先用试标小批贯通检索→支持核验→评分→报告，再完成 80 题开发运行；排除缺项、错误映射和日志问题，验证盲化核验方式。冻结协议、语料、Gold-core、方法配置和评分代码版本，登记正式可运行组别、命令与独立输出位置 |

执行依赖：P0-1 → P0-2 → P0-3；P1-4 可在 P0-1 后与标注并行，P1-5 依赖 P1-4；P1-6 可使用试标数据和固定算例并行开展；P2-7 汇合上述工作。先完成小批闭环再扩展全量，避免大批标注后才发现字段或支持组合无法评分。首轮仍不进行检索参数搜索。

本清单整理已有协议的实施依赖，不指定尚未核验的外部资产路径，也不表示已有工程代码已经适配新协议。后续实施涉及本目录以外的代码、语料或输出位置时，应先明确对应范围与实际路径。
