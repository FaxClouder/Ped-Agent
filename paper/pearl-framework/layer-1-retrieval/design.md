# PEARL Retrieval 评价设计

*英文科学文献检索的评价对象与执行顺序 · status: plan · protocol: retrieval-v0.2 · 2026-09-29*

本文与 [metrics.md](metrics.md)、[experiments.md](experiments.md) 共同替代本目录原有的旧资产草案。协议已给出指标和实验安排；[原文来源快照](../datasets/retrieval-corpus/README.md)已固定，新题集、标注、运行配置及评分器尚未构建，不能将设计状态表述为已验证结果。

## 1. 研究问题

PEARL 规定评价对象、证据语义、指标和比较规则。BM25、dense、融合、重排、解析和切块是具体实验中的配置变量。更换算法不改写评价定义。

当前范围为英文文献语料与英文查询，每个 underlying intent 使用一个冻结的英文问题。新题集、来源清单、解析输出、chunk、索引、标签和排名均独立构建，旧评估资产不进入协议。

| 研究问题 | 可测量结论 | 实验 |
| --- | --- | --- |
| RQ1 完整检索 | 在相同语料、切块和 K 下，方法能否找齐至少一条完整证据路径？ | R1–R4 的 CEGR@10 |
| RQ2 部分覆盖与排序 | 未找齐时缺多少；完整证据在多长的排名前缀中出现？ | BestGroupCov 与 CompleteMRR |
| RQ3 检索阶段的贡献 | dense、融合、重排各自相对预先指定的对照有何差异？ | 固定的三个配对比较 |
| RQ4 可定位的失败 | 漏失发生于来源处理、候选生成、截断还是最终排序？ | 分阶段记录与核验，见 [失败分类](failure-taxonomy.md) |

不把任一方法预设为有效，也不设置达到某个分数才增加实验组的事后规则。结论限定于本次冻结英文语料与题型分布。

## 2. 评价单位与证据语义

一个 evidence group 是足以独立支持参考答案的一组必要证据。组内 AND，替代完整组之间 OR。例如 `(A AND B) OR (C AND D)`，只找到 A 与 D 不能算完整成功。

每项必要证据包含事实、对象、条件、单位及来源约束。单项事实可以有多个等价来源，也可以需要多个原文片段共同支持。原文片段锚定文档版本和位置，chunk ID 只属于某次解析／切块配置的映射结果。

若事实与条件来自同一实验才成立，应将实验身份纳入证据要求。不能把研究甲的宽度和研究乙的流量拼成一条原文没有支持的关系。不同但各自完整的研究路径应分别成组。跨论文比较需要的各方材料放在同一完整组内共同满足。

主指标采用 **CEGR@10（完整证据组成功率）**，部分覆盖采用 **BestGroupCov@10**，完整证据首次齐备的排序诊断采用 **CompleteMRR@10**。这些是 PEARL 的明确操作化名称，受到必要信息检索研究启发，不宣称逐字复现 RARE 或标准首个相关结果 MRR。公式、边界和固定算例见 [metrics.md](metrics.md)。

## 3. 输入、输出和层间边界

| 对象 | 内容 |
| --- | --- |
| 检索输入 | 冻结英文 query、允许检索的来源清单、索引和方法配置 |
| Gold 输入 | 参考答案、非空完整证据组、必要证据、来源支持片段、质控和版本信息 |
| 方法输出 | 完整运行状态；最终排名至少前 100 项或全部可返回结果；各阶段候选及 provenance |
| Layer 1 评分输入 | 最终排名的前 K 个原始 child 文本，K=1/5/10/20，主报 10 |
| Layer 2 输入 | 由 parent 展开、去重和预算截断产生的最终上下文，另存文本与处理轨迹 |

检索器只能读取 query 和允许检索的语料，不能读取 Gold 证据、参考答案或测试评分。评分器不使用模型分数大小判断事实支持。资源和页码命中只能作为定位诊断。

Layer 1 对原始 child 计分；parent 额外补出的信息只影响 Layer 2。上游检索失败与下游上下文不足可以同时被观察，但不能合计成两个新增根因。Layer 2 自身充分性分数仍按其协议记录，不能因归因规则而把不足改记为充分。

## 4. 数据与标注方案

首轮目标为 **80 个开发 intent＋200 个独立评估 intent**，均为相对于冻结语料可回答的英文检索问题。每个 intent 一个主查询；四个主要题型按 20/50 分配，具体规则见 [experiments.md](experiments.md)。这些是计划配额，不是已存在数据，也不保证统计功效。

先确定语义 Gold，再检索、核验输出内容与 Gold 的映射：

1. 选取并版本化英文来源，确认原文确有答案；在原文上标注事实、条件、证据组与支持片段。
2. 按 intent 和近重复问题家族划分开发／独立评估集；同一问题的改写不能跨集。
3. 以新解析输出建立 child 映射，记录目标原文在解析、切块和索引中是否保留。处理丢失不作为删题理由。
4. 开发集用于调试和预先允许的配置选择；评估集的 query、语义 Gold 和方法配置在评估运行前冻结。
5. 密封保存各方法的评估排名，再合并候选、隐藏方法名和排名进行支持核验；所有方法共享同一映射版本，核验完成后才汇总评分。

输出核验可补充既有证据要求的等价支持来源，但不能据方法成绩改变事实、组结构、条件或判定阈值。新增完整推理路径或改动参考答案须另建语义 Gold 修订版，保留原版本结果并对所有方法一致复核，不静默替换预定主分析。

采用 Agent 辅助标注时保存模型、提示、原文引句与核验记录，明确标签来源；只有实际完成相应人工核验才能声明人工 Gold。标注可信度与可运行性分别报告。

## 5. 本轮对照与后续扩展

主矩阵 R1 BM25、R2 dense、R3 RRF、R4 RRF＋reranker 共享新语料、解析、child、query 和 Gold。模型及参数属于本次实验，定义见 [experiments.md](experiments.md)。

解析和切块改进在独立消融中一次改变一个因素，重新核验来源到 child 的映射；同时报告 K 和 token 预算下的成绩。它们不并入本轮四方法的纯检索比较。语料变化须独立报告；不能把新来源提供的额外证据算成检索算法改进。

## 6. 执行顺序与完成标准

| 阶段 | 交付 | 进入下一阶段的条件 |
| --- | --- | --- |
| 协议 | 本目录五份设计文档及固定算例 | 指标、对照、统计和报告互相一致 |
| 新资产 | 80/200 题集、语义 Gold、来源清单、新解析／索引 | 样本与出处可追溯；划分和标签版本明确 |
| 执行准备 | 配置 manifest、评分器、分阶段日志适配 | 所有必填版本／哈希齐全；固定算例通过；无旧资产依赖 |
| 开发 | R1–R4 开发排名、盲化支持核验和开发报告 | 参数与运行流程冻结，测试不参与选择 |
| 独立评估 | 冻结排名、统一支持映射、逐题评分 | 核验覆盖满足各报告深度；运行错误解决或明确标记未执行 |
| 报告 | 主表、预设比较、失败分类和成本 | 结果可回溯；统计与缺失规则按协议执行 |

具体执行清单在 [experiments.md](experiments.md)。本次文档调整完成协议设计，不代表评分器、80/200 数据或模型实验已执行。
