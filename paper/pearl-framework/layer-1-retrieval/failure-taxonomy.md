# PEARL Retrieval 失败分类与诊断

*基于内容命中、阶段记录和有限排名深度的归因 · status: plan · protocol: retrieval-v0.2 · 2026-09-29*

评价定义见 [metrics.md](metrics.md)，必存记录见 [experiments.md](experiments.md) §5。分类依据是实际证据内容和处理轨迹，Page-Hit 不再作为唯一触发条件。

## 1. 分类单位

对每个有效 intent 保存各完整组及每项必要证据的支持情况。主检索失败是 CEGR@10=0，但也核验成功题的重复片段、无关文本及其他潜在缺陷。一个失败 intent 可以涉及多条原因；原因计数不能相加当总失败题数。

完整组之间是替代关系。只有每个可接受完整组都被阻断，才是整题失败；某个未选替代组有缺失不能证明整题因它失败。支持核验不完整时标 `unresolved`，不能强行选最像的原因。

## 2. 运行和标签状态先检查

| 状态 | 判据 | 处理 |
| --- | --- | --- |
| EXEC_ERROR | 超时、文件损坏、模型错误、缺失排名或来源不匹配 | 执行错误；修复后以新 run 重跑，不作为普通质量漏检 |
| GOLD_INVALID | 空组、缺必要条件、参考答案冲突且无法界定，或语料内不存在任何完整支持路径 | 统一仲裁；记录变更，不按某一方法选择性剔除 |
| SUPPORT_UNRESOLVED | 报告深度内仍有候选或组合可能支持但未核验 | 暂缓该深度正式计分；保留未决计数 |
| VALID_MISS | 非空有效 Gold、成功运行且支持判断可用，CEGR@10=0 | 进入下列诊断 |

在冻结语料中有证据、但某次解析／切块／索引未保留时，属于质量失败，不能改记 Gold 无效。

某个替代来源不在冻结语料，不自动使整题无效；须先检查是否仍有其他完整的语料内支持路径。将无效来源标出并统一核验，保留仍可回答的 intent。

## 3. 证据可用性与检索阶段

| 代码 | 判定所需证据 | 可作出的结论 |
| --- | --- | --- |
| P_PARSE | 原文支持片段存在，但在冻结 canonical 解析文本中缺失或被破坏 | 解析损失；须核对表格、单位、条件和脚注 |
| P_CHUNK | canonical 保留信息，但所有有资格的 child 联合也无法支持目标要求 | child 构建或资格策略损失；拆到多 child 本身不算损失 |
| P_INDEX | 在与 manifest 一致的冻结索引中，遗漏了有资格且承载证据的 child | 索引构建内容遗漏；保留在质量分母 |
| R_CANDIDATE_UNOBSERVED | 已核验索引含支持，实际各通道保存候选中未见完整支持 | 候选阶段保存范围内未召回；不推断精确全库排名 |
| R_FUSION_CUTOFF | union 中可组成完整组，但 R3 的前 100 已无法组成 | 融合排序和候选截断造成证据丢失 |
| R_TOPK | 最终前 100 中可组成完整组，而前 10 不可 | 最终排序未在 K=10 内集齐；报告首次完成排名 |
| R_RERANK_LOSS | 同一 R3 前 100 候选，R3 前 10 完整而 R4 前 10 不完整 | 重排使完整证据移出 Top-10 |
| R_SCOPE_MISMATCH | 返回文字主题接近，但对象／场景／单位／条件不满足冻结要求 | 内容不支持；可与上述阶段标签并列 |
| UNRESOLVED | 无足够 canonical、索引、候选或支持核验记录 | 无法归因，不把未知当某种算法失败 |

解析、child、索引、union、最终前 100 与前 10 应分别判断组完整性。某层已有一组完整证据，不能因为另一组损失就把整题失败归因于该层。只有相邻阶段从“至少一组完整”变成“不完整”，才可直接记录该阶段丢失了已知完整路径；没有这种证据时保留单项缺失轨迹与多因并存。

运行时加载了错误索引版本或指纹与 manifest 不符，属于 EXEC_ERROR，修复重跑；它与上表有效冻结索引本身的内容遗漏不同。

诊断受已核验证据来源覆盖限制。尚未发现的替代证据可能改变判断，报告 Gold／mapping 版本和未决范围；不使用“唯一根因”表述超出核验能力。

## 4. 有限深度下的排名口径

D=100 是保存深度，K=10 是主评分深度。两者用途不同：

- 前 10 不完整、前 100 完整：可以给出在已存排名内的首次完成位置，例如 27。
- 前 100 未完整：只报“前 100 未观测到完整组”，或者 `not_observed_within_D`；不能填 101 或无穷作为已测真实名次。
- 判断某项支持是否存在于索引：查完整索引身份／文本和来源映射，不能根据 Top-100 缺席下结论。
- 更深诊断检索只能另存为事后分析，不回写主排名，也不冒充原方法运行。

当第 21–100 名存在未核验支持时，深度诊断为未决；若前 20 已核验完毕，K≤20 的正式成绩可以保留。

## 5. parent 补证与 Layer 2

| child 内容状态 | 最终组装上下文 | 记录 |
| --- | --- | --- |
| 完整 | 充分 | 保留两层各自观察 |
| 完整 | 不足 | Layer 2 新增损失，检查去重、截断和组装 |
| 不完整 | 充分 | parent／上下文处理挽回；Layer 1 分数不回填 |
| 不完整 | 不足 | 记录持续缺失；不重复累计为两层新增根因 |

`parent_recoverable` 只是待检验假设。只有保存实际展开与最终送入生成器的文本，并核验缺失内容确实进入最终上下文，才能记录 `parent_recovered=true`。本轮仅运行 Retrieval 时，Layer 2 状态填“未执行”，不根据 parent ID 猜测充分性。

## 6. 固定诊断算例

| 场景 | 期望判断 |
| --- | --- |
| 同页背景 child 进入 Top-10，事实只在未返回段落 | 页定位可命中，内容不命中；继续查处理与排名证据 |
| 一个事实拆到排名 2、7 的两个 child，联合文字完整 | 该事实在前 7 已满足，不能归为切块损失 |
| A、B 同组，分别排名 2、27 | CEGR@10=0；前 100 完整，R_TOPK，完成名次 27 |
| 标注原文存在，解析丢失表头导致数值无对象 | P_PARSE；保留在主分母 |
| 前 100 未见支持，没有全索引核验 | `not_observed_within_D`，根因未决，不记索引缺失 |
| R3 前 10 完整，R4 把必要 child 排到 15 | R_RERANK_LOSS；同一候选池支持这一归因 |
| child 不含条件，parent 含条件但被上下文预算截掉 | 不能记为 parent 挽回 |

逐题报告至少包含缺失的组／证据 ID、各阶段观察、原因标签、核验文本、判定来源和未决项。汇总同时报告失败 intent 总数与各标签覆盖数，并注明标签可重叠。
