# Layer 1 失败模式分类

*检索失败的归因分类法与判定流程 · status: plan · 2026-09-28*

> 用于对 [experiments.md](experiments.md) 中 Page-Hit@10 = 0 的案例做结构化归因。目的是把"检索失败"拆成可定位、可分别改进的原因，而不是只报失败率。

## 1. 分类法

失败类别按发生位置分四组。一个案例可有多个标签，但须指出主导原因。

### L1 检索层

| 编号 | 类别 | 判定特征 |
| --- | --- | --- |
| L1.1 | 正确资源未召回 | Resource-Hit@10 = 0，Top-10 中无标注资源的任何 chunk |
| L1.2 | 资源召回但目标页排名过低 | Resource-Hit@10 = 1，标注页首次出现排名 > 10 |
| L1.3 | 跨语言词形失配 | 中文查询零命中或排名极低，同义英文查询命中 |
| L1.4 | 同资源内错页竞争 | Top-10 被同一资源的其他页占据，标注页被挤出 |

### L2 解析层

| 编号 | 类别 | 判定特征 |
| --- | --- | --- |
| L2.1 | 表格结构丢失 | 标注页含表格，chunk 文本中表格退化为无结构数字串 |
| L2.2 | 公式识别错误 | 标注页含公式，chunk 文本中公式缺失或乱码 |
| L2.3 | 跨页内容断裂 | 证据横跨两页，任一侧 chunk 均不完整 |
| L2.4 | 图表说明丢失 | 证据在 figure caption 中，chunk 未包含 |

### L3 切块层

| 编号 | 类别 | 判定特征 |
| --- | --- | --- |
| L3.1 | 证据被切分 | 必要信息横跨两个 child chunk，单个 chunk 均不充分 |
| L3.2 | 关键上下文在 parent | child chunk 缺少限定条件，条件在 parent chunk 中 |
| L3.3 | 标题与内容分离 | 章节标题与数据分属不同 chunk，导致检索信号弱 |

L3 类失败在 Layer 1 记为失败，但其中一部分可由 Layer 1.5 的 parent 展开挽回。判定时须标注"是否可由 parent 展开覆盖"，供层间归因使用。

### L4 标注层

| 编号 | 类别 | 判定特征 |
| --- | --- | --- |
| L4.1 | 页级定位不准 | 人工核查发现证据实际不在标注页 |
| L4.2 | 必要信息定义过宽或过窄 | 标注的必要信息与问题实际所需不符 |
| L4.3 | 等价来源未识别 | 检索命中了表达同一事实的其他资源，但未在标注中 |
| L4.4 | 标注资源不在索引 | 标注的 `resource_id` 在当前索引中不存在 |

L4 类不是系统失败，是标签缺陷。这类案例须从"检索失败"计数中分离出来单独报告，否则会把标注问题算作模型缺点。L4.3 尤其重要：它直接对应 [metrics.md](metrics.md) §6.3 所述的低估。

## 2. 判定流程

```mermaid
flowchart TD
    S[Page-Hit@10 = 0] --> A{Resource-Hit@10}
    A -->|0| B{标注资源在索引?}
    B -->|否| L44[L4.4 标注资源缺失]
    B -->|是| L11[L1.1 资源未召回]
    A -->|1| C{标注页首次排名}
    C -->|> 10| D{Top-10 是否同资源其他页}
    D -->|是| L14[L1.4 错页竞争]
    D -->|否| L12[L1.2 排名过低]
    C -->|不存在| E[人工核查标注页 chunks]
    E --> F{证据是否在该页}
    F -->|否| L41[L4.1 定位不准]
    F -->|是| G{chunk 文本是否完整承载证据}
    G -->|否| H[判定 L2.x 或 L3.x]
    G -->|是| I{是否命中等价来源}
    I -->|是| L43[L4.3 等价来源未识别]
    I -->|否| L12
```

判定 L1.3 需要额外一步：对该题用英文查询重跑同一方法，命中则标 L1.3。这项对照在 [experiments.md](experiments.md) §6.3 的语言效应分析中已有数据，无需单独运行。

区分 L2.x 与 L3.x 的依据：单个 chunk 内文本已损坏或缺失属 L2；文本完好但被边界切开属 L3。

## 3. 案例记录格式

每个失败案例记录以下字段：

| 字段 | 内容 |
| --- | --- |
| `intent_id` | intent 标识 |
| `method` | 失败的检索方法 |
| `query` | 查询文本（含语言） |
| `ground_truth` | 标注的 `resource_id`、`pdf_page_1based` |
| `resource_hit` | 布尔 |
| `target_page_first_rank` | 标注页首次出现排名，未出现记 `null` |
| `top_10_summary` | Top-10 的 (resource_id, page) 序列 |
| `failure_categories` | 分类标签数组 |
| `primary_category` | 主导原因 |
| `parent_recoverable` | L3.x 时填，是否可由 parent 展开覆盖 |
| `human_checked` | 是否经人工核查 |
| `analysis_note` | 核查结论与依据 |

| L1.2 排名过低 | 待运行 | 待运行 | 待运行 | 待运行 |
| L1.3 跨语言失配 | 待运行 | 待运行 | 待运行 | 待运行 |
| L1.4 错页竞争 | 待运行 | 待运行 | 待运行 | 待运行 |
| L2.x 解析层合计 | 待运行 | 待运行 | 待运行 | 待运行 |
| L3.x 切块层合计 | 待运行 | 待运行 | 待运行 | 待运行 |
| L4.x 标注层合计 | 待运行 | 待运行 | 待运行 | 待运行 |

L4.x 行须与其余各行分列说明：前者是标签缺陷，不计入系统失败率。

### 4.2 深度案例

选 3–5 个典型案例做深度分析，选择标准：

- 方法间差异最大的案例（一种方法命中、另一种失败）
- 全方法失败的案例（指向底座而非检索方法）
- 疑似 L4 的案例（影响标签可信度判断）

每个案例给出：查询、标注证据、各方法的 Top-10 概要、人工核查结论、归因依据。

另选 2–3 个全方法命中的案例作为对照，说明当前配置的能力上界。

## 5. 归因结果的用途

| 主导类别集中于 | 指向的后续工作 |
| --- | --- |
| L1.3 | 查询翻译、双语术语表、跨语言检索 |
| L1.2 / L1.4 | 重排器、候选深度调整 |
| L2.x | 解析器对比实验（Layer 1 后续轮次） |
| L3.x | 切块策略对比、parent 展开规则（部分归 Layer 1.5） |
| L4.x | 标注细化与质量验证，不是检索改进 |

归因结果决定下一轮实验方向，不在本轮内执行改进。[experiments.md](experiments.md) §8 的重排触发条件与此处 L1.2/L1.4 的计数挂钩。

## 6. 边界

本分类法只覆盖 Layer 1 的召回失败。以下不属本层：

- 上下文展开后仍不足以回答 → Layer 1.5
- 证据齐备但答案错误 → Layer 2
- 答案无证据支持 → Layer 3
- 该拒答却作答 → Layer 4

L3.x 标注的 `parent_recoverable` 字段是 Layer 1 与 Layer 1.5 的归因交接点：Layer 1 记失败，Layer 1.5 据此判断展开规则是否足够。
