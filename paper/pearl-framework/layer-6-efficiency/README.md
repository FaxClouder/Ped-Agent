# Layer 6: Efficiency

*成本与效率评价 · status: plan · 2026-09-28*

Layer 6 横切所有层，计量端到端及各阶段的延迟、token、调用与轮数。评价的失败模式是**代价过高**：质量提升不足以抵偿额外开销。

## 待定义指标

来自 [framework.md](../framework.md) §3：

| 指标 | 原始口径 |
| --- | --- |
| Latency | 端到端及各阶段延迟 |
| Tokens | 输入/输出 token、上下文 token |
| Calls | LLM 调用次数 |
| Rounds | 检索轮数 |

按题型与复杂度报告分布及均值，不只报总均值——Agent 的额外开销在复杂题上集中，均值会掩盖分布差异。

## 分阶段归属

代价须按阶段记录再累计，使额外开销能归因到具体模块：

| 阶段 | 计量项 |
| --- | --- |
| 检索（Layer 1） | 检索延迟、候选深度、向量计算量 |
| 上下文组织（Layer 2） | 展开后上下文 token 数 |
| 生成（Layer 3） | 输入/输出 token、调用次数、生成延迟 |
| 验证（Layer 4 · Grounding） | claim 抽取与核验的调用与 token |
| Agent 决策（Layer 5） | 规划、充分性判断、改写的调用与 token；检索轮数 |

## 设计时须解决的问题

1. **延迟测量的可比性**：延迟受硬件、并发、网络和缓存影响。同一批实验须在相同环境下运行，并说明是否含冷启动、是否复用缓存。跨批次的延迟数字不可直接比较。

2. **主表指标的选择**：[framework.md](../framework.md) §3 允许资源受限场景用 Tokens 替换 Latency，但须保持所有方法口径一致。选择哪一项须在实验前定，不能按结果择优。

3. **质量–成本曲线的绘制**：[framework.md](../framework.md) §4 阶段 6 要求按复杂度画质量–token、质量–延迟曲线。横轴的复杂度分层依据须与题型体系一致，规划 `cost-quality-tradeoff.md` 展开。

4. **Agent 增量成本的归因**：A0–A4 消融的成本差值才是 Agent 各模块的真实开销。须与 [Layer 5](../layer-5-agentic/) 的消融配置逐一对应。

5. **token 计数口径**：输入 token 是否含系统提示、上下文 token 是否与输入 token 重复计数，须明确定义，否则不同方法的数字不可加总比较。
