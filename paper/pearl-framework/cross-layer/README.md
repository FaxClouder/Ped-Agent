## 错误传播分析

PEARL 分层归因的核心价值在于能回答"下游失败中有多少源于上游"。待定义的分析口径：

| 分析 | 问题 |
| --- | --- |
| Layer 1 → Layer 3 | 检索完整的题目中，答案正确率是多少？检索不完整的题目中呢？ |
| Layer 2 → Layer 3 | 上下文充分但答案错误的题目占比（纯生成失败） |
| Layer 3 → Layer 4 · Grounding | 答案正确但无证据支持的比例（正确但不忠实） |
| Layer 1 → Layer 4 · Reliability | 检索失败时系统是否正确拒答 |

**条件正确率**是关键量：$P(\text{答案正确} \mid \text{检索完整})$ 与 $P(\text{答案正确} \mid \text{检索不完整})$ 的差值度量检索质量对最终质量的贡献。两者都高说明检索不是瓶颈；前者高后者低说明检索是瓶颈。

Layer 1 的“检索完整”仅依据原始 Top-K child 的内容；Layer 2 的“上下文充分”依据最终组装文本。跨层分析应保存两者的四格转移，包括 child 不完整但 parent 展开后充分的挽回案例，不把资源或页定位当作内容完整。

## 设计时须解决的问题

1. **共享控制变量**：端到端对照须固定生成模型、提示、token 预算和题集。哪些可变、哪些固定须逐项列出，否则差异无法归因。

2. **Long-Context 基线的可行性**：全文塞入需要的上下文长度与新实验语料规模相关。须先核算总 token 量，再决定是否采用抽样版本。

3. **Agent 与 Static 的公平对照**：Agent 有更大的有效检索预算。对照时须同时报告检索量，或设计等预算对照组。

4. **压力测试的注入方式**：逐级加噪、移除关键证据、加入条件错配的具体操作须可复现，注入强度须分级且版本化。

5. **分层报告的样本量**：错误传播分析会把新样本切成多个子集（如"检索完整且答案正确"）。须按实际子集数量预先规定哪些分析仅作描述。
