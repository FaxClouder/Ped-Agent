## 划分原则

来自 [framework.md](../framework.md) §1：

- 统计单位是 underlying intent；中英问法与改写必须同组划分。
- 先在开发集选定 Best Static RAG，再固定其底层检索器进行 Agent 消融。
- **封存测试集不参与选择模型、阈值或提示。**

## 题型体系

来自 [framework.md](../framework.md) §4 的建议题型：

| 题型 | 标注要点 |
| --- | --- |
| 单来源事实 | 归一化规则 |
| 数值/表格 | 单位、容差、实验条件 |
| 多证据综合 | 证据组划分 |
| 跨论文比较 | 各方证据分属不同组 |
| 机制解释 | rubric 维度 |
| 条件推理 | 条件依赖显式标注 |
| 冲突证据 | 冲突状态与不可合并说明 |
| 证据不足 | 缺失什么、为何不足 |

**当前覆盖缺口**：开发集 18 题全为单组单页，多证据综合、跨论文比较、冲突证据题型无实例；拒答题不在范围内。这使 Layer 1 的 Coverage 指标退化、Layer 5 的 Hop 指标无测试用例、Layer 4 无法评测。

## 领域特异性

行人交通领域须核对：density、speed、specific flow、evacuation time、瓶颈宽度、样本规模、测量方法与场景条件。**条件不一致时不得直接合并结论。**

数值题的单位归一化对象：m/s、persons/m/s、persons/m²、秒/分钟。同一量的不同单位表达须视为等价，不同条件下的相近数值不得视为等价。

## 设计时须解决的问题

1. **测试集的规模与分层**：100 intent 如何在题型、难度、主题上分层，须与开发集的分布关系明确（同分布还是刻意更难）。

2. **开发集扩充与测试集独立性**：开发集从 18 扩充到 30 时，新增 intent 不得来自已规划的测试集，否则破坏封存。

3. **标注页位置分布**：开发集 15/18 题的标注页为第 1 页（摘要页）。测试集须避免同样的集中，否则指标偏乐观且不测量正文定位能力。

4. **双语查询的生成方式**：现有双语查询是人工撰写还是翻译产生，须记录。若为机器翻译，中英差异中混入了翻译质量因素。

5. **冻结时点**：测试集须在何时冻结、冻结后允许哪些修改（仅修正错误标注）、修改如何版本化。
