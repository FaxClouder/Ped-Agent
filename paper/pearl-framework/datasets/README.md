## 划分原则

依据 [PEARL 主框架](../PEARL-framework.md) §3–4：

- 统计单位是 underlying intent；当前每个 intent 使用英文查询，英文改写同组划分。
- 先在开发集选定 Best Static RAG，再固定其底层检索器进行 Agent 消融。
- **封存测试集不参与选择模型、阈值或提示。**

当前主实验不设置跨语言比较，也不构造中文查询或译文组。语料和查询均记录语言字段，便于检查是否符合英文单语范围；若未来扩展跨语言研究，须另立实验协议和数据版本。

本轮每个 intent 只使用一个英文主查询。互斥主层为单来源事实／机制、数值／表格、单篇多证据、跨论文比较／条件／冲突，归类优先顺序和配额见 [Retrieval 实验协议](../layer-1-retrieval/experiments.md) §1。来源、条件、表格及替代路径等交叉标签另外记录。80／200 已是冻结资产规模，不构成统计功效保证；替代完整组实际为 0，16／40 期望目标未达，分析限制已在运行前登记。

同一问题及近重复题族不得跨开发／评估集；来源论文可共用，因此本轮评价固定语料上的新问题泛化。记录共用来源和证据依赖簇。原文可回答、但某个解析或索引配置丢失证据的题保留在共同主分母；只有语料本身不支持答案时，才按预先审定的资格处理。

本次出题来源实际划为开发 32 篇、评估 74 篇，互斥且合计覆盖 106 篇；106 篇全部仍属于同一检索语料，不能据此称未见文献测试。题族审核同时检查集内及跨集，并修复语义重复，未仅依赖来源互斥或机器近似分数。

## 题型体系

来自 [PEARL 主框架](../PEARL-framework.md) §6 的题型标签；它们可以交叉，不能直接当作互斥统计分层：

| 题型 | 标注要点 |
| --- | --- |
| 单来源事实 | 归一化规则 |
| 数值/表格 | 单位、容差、实验条件 |
| 多证据综合 | 证据组划分 |
| 跨论文比较 | 同一个比较所需的各方证据在同一完整组内共同满足；另有独立完整比较路径时才设替代组 |
| 机制解释 | rubric 维度 |
| 条件推理 | 条件依赖显式标注 |
| 冲突证据 | 冲突状态与不可合并说明 |
| 证据不足 | 缺失什么、为何不足 |

题型覆盖须与拟报告的指标相匹配。若报告多证据 Coverage、跨论文或冲突诊断，新数据必须包含相应标注实例；缺少实例时不得报告该能力的效果。

## 领域特异性

行人交通领域须核对：density、speed、specific flow、evacuation time、瓶颈宽度、样本规模、测量方法与场景条件。**条件不一致时不得直接合并结论。**

数值题的单位归一化对象：m/s、persons/m/s、persons/m²、秒/分钟。同一量的不同单位表达须视为等价，不同条件下的相近数值不得视为等价。

## 设计时须解决的问题

1. **采样与配额落实**：按已定 80/200 和四个主层构建；记录主题、难度与位置分布，不能按运行结果补题或删题。

2. **开发集与测试集独立性**：按 underlying intent 分割；新增开发题不得来自封存测试集。

3. **证据位置分布**：记录摘要、正文、表格和跨页证据的占比，避免只测容易定位的片段。

4. **英文查询的构建方式**：明确问题撰写、改写和核验流程，保证各算法对照使用相同查询。

5. **冻结时点**：测试集须在何时冻结、冻结后允许哪些修改（仅修正错误标注）、修改如何版本化。
