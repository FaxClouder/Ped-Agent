# RAG 开发主线与讨论记录

*PedRAGent RAG 整体开发路线与持续设计讨论 · status: plan · 2026-10-08*

本文用于逐步记录讨论中已确认的设计原则与后续决策，已记录整体开发主线、资料筛选的 PRISMA 参考方式，以及借鉴 GROBID/TEI 的 Adobe 产物组织设计；具体算法、参数、实验安排与模块改造方案随讨论继续补充。已确认的路线不表示对应功能已经全部实现。

## 1. 已确认的整体主线

选取领域 PDF 并登记来源 → 技术预检与去重 → Adobe 解析为结构化文档 → 按章节和长度组织父块、切分检索子块 → 保存来源与版本信息 → 构建 BM25 和 BGE-M3 双路索引 → 检索、RRF 融合与重排 → 上下文恢复、去重和预算截断 → 生成带引用的答案，并开展 PEARL 分层评价。

这条链路作为整体开发主线。Adobe、BM25、BGE-M3、RRF 和父子块是当前路线的具体技术起点，后续可以通过受控实验比较和替换；模块职责与证据流转边界保持稳定。

| 阶段 | 职责 | 主要输出 |
| --- | --- | --- |
| 来源与入库准备 | 选取领域文献、登记来源、技术预检与去重 | 来源清单、PDF 身份与预检记录 |
| 结构化解析 | 提取正文、章节及表格等结构，保留原文定位 | CanonicalDocument 与解析资产 |
| 父子块组织 | 组织阅读上下文与检索单元，建立父子关系 | parent、child 及来源映射 |
| 索引构建 | 建立词法与稠密检索入口 | BM25 与 BGE-M3 索引及其指纹 |
| 检索与排序 | 双路召回、融合与重排 | 有序 child 候选及检索记录 |
| 上下文组装 | 恢复相关上下文、去重并控制预算 | 实际送入模型的证据文本与引用映射 |
| 答案生成 | 基于证据生成带引用答案，按配置进行验证 | 答案、引用及验证记录 |
| 分层评价 | 分别评价检索、最终上下文、答案和有据性 | PEARL 分层结果与失败归因 |

两项贯穿性规则：

- **来源与版本信息贯穿全流程。** 溯源不只在切块后执行；PDF、解析元素、chunk、索引、最终上下文与答案引用应能回溯到对应来源版本。
- **PEARL 贯穿评价过程。** Layer 1 评价原始检索 child，Layer 2 评价最终上下文，Layer 3–4 评价答案、忠实性、引用与可靠性；parent 恢复带来的补证不回填 Layer 1 成绩。

## 2. 固定边界与可调整范围

**固定模块职责、证据身份和评价边界；通过受控实验改进算法与编排策略，验证后再决定是否纳入默认实现。**

| 层次 | 约定 | 示例 |
| --- | --- | --- |
| 整体职责与证据链 | 作为长期主线固定 | 来源管理、解析、切块、索引、检索、组装、生成及分层评价 |
| 具体算法与配置 | 允许通过实验比较和替换 | 解析方法、切块边界与长度、检索模型、融合与重排、上下文选择、生成与验证策略 |
| 模块间证据传递 | 允许按明确契约改进，保持身份与溯源 | child/parent 映射、上下文交付、引用绑定与预算记录 |
| 执行控制方式 | 从静态流程分阶段演进 | 查询分解、迭代检索、针对缺口补证、停止与拒答 |

因此，后续研究不限于某个中间模块的算法替换，也包括证据如何在模块之间传递，以及这些模块如何被调用和编排。例如，“证据不足时再检索一轮”改变执行次数与顺序，但仍复用同一套检索、组装与生成能力。

## 3. 开发与实验的关系

先建立可核对的静态 RAG 链路，再研究有限 Agentic RAG。静态底座中的算法仍可独立演进；Agentic 对照使用明确冻结的底座版本。

- **工程整合：** 接通现有实验链路与模块代码，核对配置、检索结果、上下文和引用绑定。这属于基础能力整合，不全部归为算法实验。
- **方法实验：** 围绕明确问题比较算法或控制策略，声明变化因素、输入版本、预算和评价口径。
- **采纳决策：** 实验配置和结果不自动成为模块默认；采纳时记录理由、适用范围，并更新实现与当前文档。

以上确认不选定新的默认参数，不启动实验，也不把此前讨论中的具体阶段建议视为已批准的执行计划。

## 6. 资料筛选：PRISMA 参考方式

### 6.1 定位与适用边界

PRISMA（Preferred Reporting Items for Systematic Reviews and Meta-Analyses）是系统综述的报告规范，帮助透明报告检索、筛选与纳入过程。它不直接提供领域文献质量评分标准，也不替代研究方法设计。PRISMA-S 是文献检索报告扩展，提供 16 项报告条目，补充检索来源、策略、日期及记录管理等说明。

本项目采用“**参考 PRISMA 2020 与 PRISMA-S 的语料筛选与记录流程**”这一定位，服务于领域文献和法规标准的语料建设。借鉴相关条目不表示项目已经完成系统综述，也不据此宣称完全符合 PRISMA。领域相关性、研究质量及法规适用性标准需分别设计。

### 6.2 筛选流程与记录

在整体主线的“来源与入库准备”阶段细化以下流程：

**确定范围与筛选条件 → 检索和登记 → 去重 → 初筛 → 全文筛选 → 确认纳入 → 技术预检 → Adobe 解析 → 解析结果核查。**

全文筛选针对原文进行，不要求先完成 Adobe 结构化解析。资料筛选与技术处理分别记录；符合纳入条件但解析失败的资料，记为技术处理失败，不改写为学术筛选不合格。

| 环节 | 拟落实的记录要求 |
| --- | --- |
| 范围与条件 | 筛选前明确主题、资料类型、语言、年代等条件及理由，保存规则版本 |
| 检索 | 记录数据库或机构网站、平台、完整检索式、日期、限制条件、结果数量与导出来源 |
| 去重 | 记录判重方法、重复数量、保留身份及版本关系；区分检索记录、文献和研究，不把多个报告自动算作多个独立研究 |
| 初筛与全文筛选 | 记录阶段、决定、规则版本；全文排除逐篇保留具体原因，区分未获取全文与全文筛选后排除 |
| 执行与复核 | 如实记录人员或 Agent、工具与版本、复核方式及分歧处理；不把 Agent 评审标成人工评审 |
| 数量汇总 | 记录检索、去重、初筛、全文获取、全文筛选及最终纳入数量，形成可核对的流程表或图 |
| 技术处理 | 单独记录预检、Adobe 解析及解析结果核查状态，不与资料筛选的排除原因混用 |

领域文献可采用标题／摘要初筛与全文筛选。法规标准按发布机构、适用范围、版本和效力状态制定独立规则，不强套摘要筛选或论文质量分数。这是本项目的适配设计，不是 PRISMA 对法规筛选的专门规定。

## 7. Adobe 解析产物组织：借鉴 GROBID/TEI

### 7.1 目标与范围

**保留 Adobe PDF Extract 解析链路，借鉴 GROBID/TEI 对文档区域、元素及引用关系的组织方式。** 本节讨论 Adobe 返回结果如何组织为可追溯、可复用的 RAG 输入；不引入 GROBID 运行依赖，不安排解析器替换、双路解析或融合实验。

GROBID 是面向科技论文的解析工具，TEI XML 是其结构化输出形式。这里参考的是文档模型中的区域划分、元素身份与关联机制，不要求把现有 Python/JSON 契约转换成 TEI XML。表达格式本身不保证识别正确，也不能补回 Adobe 未识别的信息。

### 7.2 当前保存与转换行为

依据 [Adobe 转换代码](../Knowledge-Base/src/ped_knowledge/parsing/adobe.py)、[导入流程](../Knowledge-Base/src/ped_knowledge/ingestion/__init__.py)及[规范文档契约](../Knowledge-Base/src/ped_knowledge/contracts/__init__.py)，当前行为为：

| 层面 | 当前行为 | 含义 |
| --- | --- | --- |
| Adobe 原始响应 | 成功导入时把返回的 ZIP 原样保存为 `derived/<resource-id>/<sha>/adobe/extract.zip` | 保留 API 实际返回的 JSON 和附件；不等于确认 PDF 内容全部被识别 |
| 规范文档 | 转换成 `CanonicalDocument`，保存元素类型、文本、页码、位置框、顺序、章节路径和表格数据 | 已有结构化基础，无需重建一套平行文档模型 |
| 参考文献边界 | 转换遇到参考文献标记后停止处理后续元素 | 原 ZIP 不受影响，但后续内容可能没有进入规范文档 |
| 表格 | 保存 `table_data`，并生成按行拼接的文本 | 原始表格资产与下游文本表达是不同层面，需核查转换保真程度 |
| 元素关联 | 当前核心契约没有专用的文内引用目标关系字段 | 图表及参考文献关系是否存在于 Adobe 响应、如何映射，仍需核查 |

若内容已存在于保存的 ZIP 中，后续可以基于该 ZIP 重新转换；不必因此重新调用 Adobe。转换代码更新与解析产物版本的管理方式仍待设计，不能覆盖旧实验绑定的资产。

### 7.3 三层产物设计

目标流程为：**Adobe 原始 ZIP → 规范文档及结构关系 → 用于检索的父子块。** 三层中的基础产物已有实现，本节提出的区域与关系增强尚未实现。

| 层次 | 职责 | 设计要求 |
| --- | --- | --- |
| 原始层 | 保存 Adobe 实际返回结果，作为重新处理与核查依据 | 保留原 ZIP、PDF 身份、响应哈希及可获得的调用配置和版本信息；缺项如实记录 |
| 规范文档层 | 组织文档区域、内容元素、来源位置和关联 | 尽量保留已返回的内容及结构；转换中的合并、过滤或无法映射项应可追溯 |
| 检索层 | 按用途选择内容、切块并建立索引 | 保存选择策略版本和 chunk 到来源元素的映射；检索过滤不删除原始层内容 |

核心原则是把“保存哪些来源内容”与“哪些内容参与检索”分开。规范文档优先保存可追溯结构，正文、参考文献、附录等是否进入具体索引，由后续明确配置决定。各区域的默认索引策略本轮未定。

### 7.4 拟补充的结构组织

以下是概念设计，不是已发布字段或已实现能力；后续优先扩展现有契约，只加入实际需要的结构。

| 结构 | 拟表达的内容 | 对后续使用的作用 |
| --- | --- | --- |
| 文档区域 | 摘要、正文、参考文献、附录等区域及其来源元素 | 按区域选择内容，避免因参考文献位置而直接丢弃后续附录 |
| 元素身份与归属 | 段落、图、表、图注等元素的稳定身份及所属章节／区域 | 保留内容边界，支持不同切块策略复用同一来源 |
| 图表引用关系 | 正文引用标记与对应图表、标题和注释之间的关系 | 为定向上下文恢复提供依据 |
| 文献引用关系 | 文内引用标记与参考文献条目之间的关系 | 追溯论文转述的来源；关联成立不代表被引论文已经入库或已验证其结论 |
| 定位与变换记录 | PDF、Adobe 原始路径、页码／位置、转换版本及关系来源 | 区分解析缺失、转换损失和检索过滤，支持重建与核查 |

例如，正文“不同设施条件下的流量差异见表 3”可组织为“段落 → 引用标记 → 表 3 → 表题／表格／注释”的关系。只有目标与位置得到核实时才建立关联；是否将表格加入生成上下文，由后续组装策略和预算决定。

法规标准沿用同一分层原则，但其章、条、款及附件结构需要单独评估，不直接套用学术论文的区域分类。

### 7.5 映射与溯源规则

- Adobe 明确返回的信息按可核查的映射规则转换，保留原始元素路径或其他定位依据。
- 额外推断的关系应标明推断方式、版本和证据；无法确定的关系留空或标为 unknown，不猜测补齐。
- 图表标号、参考文献条目存在，不自动证明引用关系正确；更不能把引用关系当作论断支持标签。
- 表格应核查表头、数据、单位、注释的对应关系；不能仅凭拥有 `table_data` 或 XML 标签认定结构完整。
- 原始 PDF、Adobe 响应、转换逻辑、规范文档和 chunk 构建分别保留版本／哈希联系。新的转换结果独立命名，旧产物保持不变。

## 8. 父子切块：方案选择与实验规划

*本节为 plan：仅借鉴已有方案的实验设置，说明需要开展的实验；不引用或评价过去的实验结果，不预设优胜方案。*

### 8.1 研究对象

将三个问题分开研究：**子块怎样形成检索单元、父块怎样组织阅读上下文、检索命中后怎样恢复上下文。** 保存父块不意味着每次检索都必须展开整个父块；是否展开及展开范围是独立实验因素。

本节固定文本嵌入与检索底座，研究切块和上下文组织。嵌入模型替换、查询改写及动态 Agent 控制不与本轮因素同时变化；标题／章节前缀作为检索输入表示的单独消融处理。

### 8.2 应开展的实验

以下编号仅用于本轮规划，不沿用旧运行身份。参数为待在启动前确认并冻结的候选设置，不表示最终默认值。

| 编号 | 实验方面 | 比较方案／候选设置 | 需要回答的问题 |
| --- | --- | --- | --- |
| K1 | 子块边界与长度 | 固定 token 窗口；递归边界（段落→句子→token 回退）；章节约束（递归但不跨小节）；相邻句语义边界。各比较 256／384／512 BGE tokens 的 core 上限 | 保留边界和改变粒度如何影响完整证据召回、块数与成本？ |
| K2 | 父块组织 | 小节作为逻辑父范围；小节内按连续段落组成有长度上限的父块 | 如何保留必要上下文，同时控制父块过大造成的扩展量？ |
| K3 | 命中后上下文恢复 | child-only；命中原文段落及前后各一段；按公共父块恢复。比较 4K／8K 上下文预算 | 哪些恢复方式能补齐证据，哪些会因占用预算而挤出其他必要来源？ |
| K4 | 子块重叠 | 固定 core，在允许边界内增加 0%／10%／20% 的连续前文 | 重叠能否改善边界证据，增加多少重复文本、索引量和检索成本？ |
| K5 | 标题与章节前缀 | 正文；原文标题＋章节路径＋正文 | 结构信息作为检索输入是否改善排序？是否增加模型输入和截断风险？ |
| K6 | 表格、图注与关联内容 | 先固定公共处理规则；单独比较表格行组与必要表头／单位／注释的保留方式，以及经核实的正文—图表关系恢复 | 数值与条件是否在切块或组装中分离？关联恢复能否补齐必要证据？ |
| K7 | 端到端验证 | 选择少量完整配置，固定生成模型、提示和预算，进行重复生成与分层评价 | 检索和上下文变化能否传递为更正确、完整且引用有据的答案？ |

K2 中父块长度上限可先以 1,536 BGE tokens 作为可比的预设参考值；是否比较更多父块长度需另行确定，不能将该值称为最优。整小节作为逻辑父范围时，仍须声明实际恢复的上限和超长小节处理规则。

K6 的图表关系恢复依赖第 7 节中可核查的元素关联；尚无可靠关系时不猜测目标。该项不涉及从图片中识别曲线或数值，图像内容理解不属于此次切块比较。

### 8.3 分阶段比较，控制组合数量

| 阶段 | 安排 | 产出 |
| --- | --- | --- |
| 准备 | 冻结 Adobe 规范文档版本、内容范围、分句器、tokenizer、来源映射、公共表格规则及题集；完成少量固定案例冒烟 | 输入与配置清单、可逆来源检查、实验登记 |
| 子块比较 | K1 的四类边界 × 三档长度；初轮统一无重叠、无前缀、child-only；另设身份明确的当前实现基线 | 各配置的切块画像、真实检索结果与固定预算上下文 |
| 父块与恢复 | 冻结 K2 的公共父图，再执行 K3；只使用基线及少量子块候选，父图独立于 child 切法 | 恢复增量、放大率、去重及预算损失 |
| 有限消融 | 在冻结候选上分别执行 K4 和 K5，不同时修改两者 | 重叠与前缀的独立作用及组合复核 |
| 结构专项 | 单独执行 K6，保持其他因素一致 | 表格／关联内容的证据保留与恢复分析 |
| 答案验证 | 最终组合重新核对 Layer 1–2，再执行 K7；开发选择完成后安排符合隔离要求的独立评价 | 逐题答案、引用、分层质量及成本 |

避免一次展开边界 × 长度 × 父块 × 重叠 × 前缀 × 预算的全因子矩阵。候选数量上限、选择规则、unknown 处理、调用预算与停止条件在正式运行前写定，不根据观察到的成绩无限扩展参数搜索。

### 8.4 公共控制与比较规则

- **相同来源输入：** 同一轮使用相同 PDF 和 Adobe 规范文档快照。若第 7 节的产物组织发生变化，产生新版本并重新冻结，不与切块因素混合归因。
- **明确比较单位：** 子块长度按同一 BGE tokenizer 计数，core 上限不是平均长度。重叠和前缀附加后的实际模型输入长度另行记录；当前实现基线若使用不同计数器或重叠，须单列差异，不能解释为纯边界对照。
- **相同检索底座：** 固定 BM25、BGE-M3、RRF、重排及候选深度。可参考每通道 Top-100、RRF k=60、融合 Top-100 重排的设置；精确向量检索或 ANN 路径须明确选定并保持一致。
- **新块对应新检索：** 子块内容或检索表示改变时重新建立相应索引并实际检索；只有排名不变、仅恢复方式变化时才复用同一排名。
- **公共结构处理：** K1–K5 使用一致的表格规则和可索引内容范围。K6 单独改变结构处理方式，不把不同表格切法混入正文边界比较。
- **父块与子块解耦：** 公共父图从冻结来源结构构建，不依赖某个候选 child 边界；跨父子块保留多段来源映射。
- **两个评价视角：** 原始 child 的固定 Top-K 观察检索能力；固定 4K／8K 预算观察实际可交付上下文。相同 K 不等于相同 token 或成本。
- **可追溯组装：** 保存恢复前、恢复后、去重后及最终截断文本；按来源版本和区间去重。完整序列化上下文计入标签与来源头，另核查完整模型请求的输入限制。
- **输入表示与证据分开：** K5 的标题／章节前缀可统一用于 BM25、dense 和 rerank，解释为整体检索表示消融；前缀不自动作为回答支持证据。若要区分各通道收益，另设消融。
- **评价隔离：** 切块、父图、语义阈值、恢复策略不能读取参考答案或证据标签。语义边界阈值在无标签来源上确定并冻结；题集、参考和来源支持映射按现行评测规范登记核验。

### 8.5 评价内容与交付

| 维度 | 应记录的内容 |
| --- | --- |
| 切块画像 | 子块与父块数量、实际长度分布、超长回退、跨章节情况、重叠量及来源映射完整性 |
| 检索 | Layer 1 完整证据召回与排序，主指标可采用 CEGR@10；parent 恢复不回填 child 成绩 |

| 成本 | 一次性切块／向量化／建库成本，以及逐题检索、重排、组装和生成成本；评审成本单列 |

## 9. 离线双路索引：BM25 与 BGE-M3

### 9.1 职责与范围

**BM25＋BGE-M3 dense 作为离线建索引的固定技术底座，暂不单独开展模型选型实验。** BM25 提供词法匹配入口，BGE-M3 将检索子块编码为稠密向量，供后续语义检索使用。这里的双路是独立 BM25 与 BGE-M3 的 dense 通道，不表示启用 BGE-M3 的全部检索能力。

以 child 为两路索引共同的检索单元；parent 用于上下文恢复，本阶段不另设 parent 检索索引。原文、规范文档、child 和 parent 的身份关联继续保留。

### 9.2 建库配置约定

以下为需要落实的配置约定，具体值在相应实验启动前确认并冻结；不因总体设计收口而自动认定模块与实验配置已经一致。

| 项目 | 约定 |
| --- | --- |
| 索引成员 | 两路绑定相同的 child 集合、来源版本及切块配置；保存成员清单与内容指纹 |
| 输入文本 | 明确正文及标题／章节前缀的使用方式，与第 8 节 K5 一致；记录两路实际输入，区分检索表示与来源证据正文 |
| BM25 处理 | 固定词法分析器、大小写与数字处理、字段组成及权重，保存配置版本和指纹；语言适用范围随语料明确 |
| BGE-M3 编码 | 固定模型与权重版本、tokenizer、输入上限、向量维度、归一化、设备及精度；记录实际编码配置 |
| 超长输入 | 核查附加重叠和前缀后的完整输入，避免静默截断；如需截断，明确规则并记录影响范围 |
| 向量索引 | 声明距离度量、存储与检索实现及构建参数；精确检索和 ANN 不混称为同一实验设置 |
| 构建身份 | 绑定语料、规范文档、切块、输入表示、模型、分析器和相关代码的版本／哈希 |

### 9.3 验证与更新

- 核对两路 child ID 集合、数量和内容绑定，检查缺失、重复及非预期额外成员。
- 核对向量数量与维度，检查非有限值、异常零向量及归一化是否符合配置。
- 用固定案例检查索引可读性、来源回溯和版本失配检测；建库通过不等于检索效果已获验证。
- 来源内容、切块、检索表示、分析器或编码模型变化时，生成新的相应索引版本；未变化的资产仅在身份核验一致时复用。
- 新索引使用独立命名的输出目录，保留构建清单、配置、核验结果及成本，不覆盖旧实验绑定的产物。

双路召回深度、查询处理、RRF 融合、重排和在线筛选属于后续 Online Retrieval 讨论；切块实验需要这些参数时，在实验协议中先固定。
