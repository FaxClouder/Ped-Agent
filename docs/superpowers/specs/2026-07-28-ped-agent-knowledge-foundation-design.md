# Ped-Agent 行人流知识底座设计

- 日期：2026-07-28
- 状态：已完成方案确认，等待书面规格复核
- 当前范围：知识库、RAG 检索与评测
- 暂缓范围：记忆详细设计、LLM 回答、轨迹分析、安全评估和实验分析实现

## 1. 项目目标

Ped-Agent 最终是面向行人流研究的统一问答与分析智能体。系统将利用可追溯的文献、法规、标准、数据集关系和后续轨迹分析结果，支持以下研究任务：

- 分析行人流领域问题并返回可核验依据；
- 评估实验方案、数据选择和指标设计是否合理；
- 对已有轨迹数据开展多层次分析；
- 对行人流场景进行安全与规范符合性评估；
- 为研究实验、结果解释和论文论证提供证据支撑。

当前不一次性建设完整智能体。第一阶段只建立可信、可检索、可评测的知识资产底座，为后续能力提供稳定依据。

## 2. 第一阶段范围

第一阶段完成四个模块：

1. **资料收集与导入**：接收行人流文献、法规、标准、题录和来源记录，形成候选资料。
2. **知识库管理**：在本地保存原文和规范化信息，核验来源、版本与有效性，决定资料能否正式进入知识库。
3. **RAG 检索**：根据查询从正式知识资产中召回相关原文片段，返回排序结果和定位信息。
4. **检索与知识库评测**：使用人工标注测试集评估检索准确度，同时检查资料完整性、解析质量、版本有效性和可复现性。

本设计中的 RAG 只包含资料检索和结构化证据包，不包含 LLM 回答生成。

## 3. 明确不做的内容

第一阶段不实现：

- LLM 答案生成、对话编排和声明校验；
- 轨迹读取、指标计算、风险诊断和可视化分析；
- 安全评估、实验方案评估和管理建议生成；
- memU、Mem0 或其他长期记忆方案的具体数据模型与实现；
- 在线资料上传、在线元数据编辑、审核工作流、任务看板、角色权限和多人协作；
- 云端对象存储、云数据库或分布式检索服务。

上述能力只在总体架构和前端导航中保留位置，不提前实现业务逻辑。

## 4. 总体架构

项目采用本地优先的模块化单体。一个本地后端承载知识加工、事实存储、检索、评测和只读 API；前端是 Ped-Agent 的统一研究工作台。

核心数据链路为：

```text
文献/法规/题录
    -> 本地导入与质量校验
    -> 本地事实源
    -> 统一索引模块
    -> 检索候选 ID
    -> 回查事实源
    -> 结构化证据包
```

架构遵守以下约束：

- 本地事实源是唯一权威数据来源；
- 检索索引是从事实源派生的可重建数据，不形成第二套事实库；
- 索引只负责发现候选资源或切块 ID；
- 证据包必须回查事实源后生成；
- 事实源与索引不一致时，以事实源为准；
- 默认检索不得返回候选、未批准、废止或被替代且当前无效的资料。

## 5. 本地事实源

本地事实源由两部分组成：

- **SQLite Catalog**：保存资料身份、类型、版本、来源、元数据、法规效力、处理结果、正式纳入状态、资料关系和运行记录；
- **内容寻址文件库**：按 SHA-256 保存或登记原始文件，避免重复原文并支持版本核验。

事实源还保存可追溯的规范正文片段。每个片段至少能够定位到：

- 资料稳定标识与具体版本；
- 原文文件；
- 文献页码与章节，或法规条款号与页码；
- 解析器及其版本；
- 正式纳入和当前有效状态。

资料解析成功不等于资料可信，资料审核通过也不等于索引已经构建完成。治理结论、技术处理结果和索引状态必须分开记录，但第一阶段不建设前端审核页面。

## 6. 知识来源与组织

### 6.1 文献来源

试点和正式库围绕后续研究任务组织，而不是只按宽泛关键词积累论文。首批主题包括：

- 行人流基础理论、基本图、密度、速度、流量、瓶颈与拥堵；
- 受控实验、现场观测、实验方案和测量方法；
- 轨迹数据、轨迹处理、指标计算和数据质量；
- 混合流、疏散、安全风险和场景评估。

文献记录需要保留 DOI 或其他稳定标识、研究场景、证据类型、主要方法、使用的数据集和与项目的关系。正式扩库应优先建立“数据集—实验—论文”证据链，区分真实使用或评测数据集与仅在正文中提及数据集。

### 6.2 法规与标准来源

法规与标准以中国体系为主，国际资料作为对照：

- 中国国家标准、行业标准、地方标准和相关规范；
- 行人交通设施、无障碍、建筑疏散、消防安全、公共场所和应急管理相关文件；
- ISO、NFPA 等关键国际标准或指南，用于比较适用范围和指标差异。

法规记录必须明确文号、发布机构、适用地区、效力层级、版本、生效状态、生效/废止日期和替代关系。历史版本保留用于研究追溯，但默认搜索优先返回当前有效版本。

## 7. 资料加工与正式纳入

资料加工全部通过本地脚本、CLI 和 Manifest 完成，不在前端操作。基本流程为：

1. 将原文和题录放入本地待处理目录；
2. 构建并校验结构化 Manifest；
3. 校验稳定标识、来源、文件存在性、大小、哈希、页数和版本关系；
4. 解析正文，清除重复页眉页脚等噪声，保留页码、章节或条款定位；
5. 按可追溯边界生成规范切块；
6. 运行资料质量检查和人工抽检；
7. 将合格资料标记为正式纳入；
8. 从事实源增量构建或重建检索索引；
9. 运行 Gold Set 评测，通过后更新正式资料库快照和报告。

批处理允许单份资料失败而其他资料继续完成。每次运行必须生成成功项、失败项、原因和重试建议。

## 8. 统一索引与检索

索引构建与用户查询是两个运行时序，但属于同一个索引模块。

### 8.1 索引构建

- 第一阶段必须启用 SQLite FTS5/BM25；
- 索引输入只来自正式事实源；
- 支持增量更新、完整重建、版本记录和失败重试；
- 索引失败不得破坏或回滚事实源；
- 向量检索是未来可插拔后端，不是第一阶段依赖。

### 8.2 查询与证据包

查询流程为：

1. 接收查询、资料类型和过滤条件；
2. 使用已启用的检索后端返回候选 ID 和相关度；
3. 根据 ID 回查事实源；
4. 过滤无权使用或当前无效的资料；
5. 返回结构化证据包。

证据包至少包含资料标题、类型、版本、来源、当前有效状态、命中原文、页码或条款号、章节、相关度和稳定标识。没有匹配证据时明确返回空结果，不生成猜测性回答。

## 9. 前端定位

`frontend/` 是 Ped-Agent 最终统一的研究工作台，而不是一次性的资料展示页。

总体导航预留：

- 知识库；
- 智能问答；
- 轨迹分析；
- 安全评估；
- 实验支持。

第一阶段只实现“知识库”，包括：

- 文献和法规列表；
- 类型、主题、年份、效力状态等筛选；
- 关键词检索；
- 资料详情；
- 命中原文、页码、条款和版本信息展示。

第一阶段可预留其他页面的导航和路由位置，但不实现页面逻辑。前端不包含上传、编辑、解析、切块、索引构建或审核操作。

前端通过后端只读 API 获取资料。第一阶段 API 只需覆盖资料列表、资料详情和检索三类能力。

## 10. 错误处理

- 文件、哈希或关键元数据校验失败：不进入正式事实源，保留明确失败记录；
- 正文解析失败：原文安全保留，派生结果隔离，修复后可重试；
- 单份资料失败：不回滚同批次已经成功的其他资料；
- 索引构建失败：事实源保持有效，标记索引未就绪或继续使用已验证的旧索引；
- 索引与事实源版本不一致：检索接口返回状态警告，正式证据仍以事实源为准；
- 无检索结果：返回空证据和实际使用的过滤条件；
- 法规失效或被替代：保留历史资料，但默认从当前有效检索范围移出。

## 11. 评测体系

第一阶段不评估 LLM，只评估知识库、检索和工程可复现性。

### 11.1 知识库质量

- 资料身份、来源、版本和审核记录完整率；
- 正文解析成功率；
- 页码或条款可定位率；
- 重复文件和重复版本率；
- 法规当前/失效状态准确率。

### 11.2 检索质量

使用人工标注的 Gold Questions，为每个问题指定正确资料、页面或条款。核心指标包括：

- Recall@K；
- MRR；
- nDCG；
- 页码/条款命中率；
- 未批准、失效资料泄漏率。

### 11.3 工程质量

- 重复导入幂等性；
- 索引完整重建能力；
- Manifest、配置、输入哈希、索引版本和报告可追溯；
- API 与 CLI 检索结果一致；
- 前端可以完成资料浏览、搜索和证据定位。

## 12. 阶段路线与验收

### 阶段 1：方案基线与真实试点

- 约 20 篇领域文献；
- 约 8 份法规与标准；
- 约 30 个 Gold Questions；
- FTS5/BM25 离线检索；
- 资料身份、来源、版本和纳入记录完整率为 100%；
- 正文解析和页码/条款定位成功率不低于 90%；
- Gold Recall@5 不低于 0.80；
- MRR 不低于 0.70；
- 页码/条款命中率不低于 0.75；
- 未批准或当前无效资料默认检索泄漏率为 0；
- 索引能够从事实源重建，重复导入不产生重复资产。

### 阶段 2：正式知识库建设

- 规划达到 120 篇以上文献；
- 规划达到 40 份以上法规与标准；
- 扩展到 100 个以上 Gold Questions；
- 按主题、年份、场景、方法、数据集和法规效力建立覆盖配额；
- 根据试点失败样例调整资料清洗、切块、标签和检索配置；
- 建立持续扩库、版本更新和评测回归流程。

阶段 2 的最终配额应在阶段 1 结束后依据实际缺口校准，而不是为了满足数量引入低质量资料。

### 阶段 3：检索增强与记忆决策

- 根据 BM25 失败样例决定是否加入向量召回、融合和重排；
- 调研并比较 memU、Mem0 等记忆方案后，再确定记忆类型、治理边界和数据模型；
- 逐步接入智能问答、轨迹分析、安全评估和实验支持模块。

## 13. 项目结构

```text
Ped-Agent/
├─ backend/
│  ├─ src/ped_agent/
│  │  ├─ library/          # 事实源与资料访问
│  │  ├─ ingestion/        # metadata、解析与切块
│  │  ├─ retrieval/        # FTS/BM25 与检索接口
│  │  ├─ evaluation/       # Gold Set 与指标
│  │  └─ api/              # 最小只读 API
│  ├─ tests/
│  └─ storage/library/     # 本地资料库；不提交 Git
│     ├─ inbox/
│     ├─ objects/
│     ├─ catalog/
│     ├─ indexes/
│     ├─ derived/
│     └─ reports/
├─ frontend/               # 统一研究工作台
├─ research/
│  ├─ manifests/           # 可复现导入清单
│  ├─ experiments/         # Gold Questions、配置和摘要报告
│  └─ sources/             # 来源与收集记录
├─ docs/                   # 规格、ADR 和调研文档
├─ scripts/                # 本地处理入口
└─ README.md
```

原文、SQLite 数据库、解析派生物和检索索引都位于 `backend/storage/library/`，不直接放在项目根目录，也不提交 Git。可复现的 Manifest、Gold Questions、配置和摘要报告保存在 `research/`。

## 14. 预留接口边界

后续模块共享稳定的证据包，而不直接读取知识库存储内部结构：

- 智能问答消费检索证据包并生成带引用回答；
- 轨迹分析输出结构化指标与事件证据；
- 安全评估组合轨迹证据、法规条款和领域文献；
- 实验支持读取文献方法、公开数据集关系、评测配置和实验结果；
- 记忆模块的具体接口在完成 memU 等方案调研后单独设计。

第一阶段只保证知识库和检索输出可以被这些模块消费，不实现对应消费者。

## 15. 设计结论

第一阶段不是建设完整的知识管理平台，也不是开发问答产品。它要交付一个小而可靠的研究知识底座：资料通过本地可复现管线进入权威事实源，BM25/FTS 从事实源构建可重建索引，前端通过只读接口展示资料和原文证据，Gold Set 持续验证检索质量。试点成功后再扩展正式资料规模，并依据真实失败样例决定向量检索、记忆和其他智能体能力。
