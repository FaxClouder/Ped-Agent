## ✅ 结论先行：**不是问题，这是标准做法**

### 关键区别

| 维度 | 深度学习 | RAG 评测 | 是否类比 |
|------|---------|---------|---------|
| **被评测对象** | 模型参数 | 检索算法 | ❌ 不同 |
| **"训练"是什么** | 用数据更新参数 | 索引文档（无参数更新） | ❌ 不同 |
| **"测试"是什么** | 预测新样本 | 检索已索引文档 | ❌ 不同 |
| **泄露风险** | 模型记住测试样本 | 检索器无法"记住" | ❌ 不存在 |

**核心差异**：
- **深度学习**：模型在训练集上**学习参数**，如果测试集泄露，模型会"记住"答案
- **RAG 检索**：检索器**不学习文档内容**，只是建立索引，无法"记住"哪个问题该返回哪个文档

---

## 📚 学术界的标准做法

### 1. 信息检索（IR）的经典范式

[**Introduction to Information Retrieval**](https://nlp.stanford.edu/IR-book/pdf/08eval.pdf) (Stanford):
> "Information retrieval evaluation revolves around a **document collection**, a set of **queries**, and **relevance judgments**"

**标准流程**：
1. 固定文档集（Document Collection）
2. 构造查询集（Queries）
3. 标注相关性（Relevance Judgments）

**✅ 文档和查询来自同一领域是标准做法**

---

### 2. BEIR Benchmark 的"零样本"定义

[**BEIR: Zero-shot Evaluation**](https://arxiv.org/html/2104.08663):
> "Zero-shot evaluation means the model is **not fine-tuned on the target task**, not that it hasn't seen the documents"

**关键洞察**：
- ❌ 错误理解：零样本 = 模型没见过文档
- ✅ 正确理解：零样本 = 模型没在**这个检索任务**上训练

**示例**：
- BEIR 在 18 个数据集上评测
- 每个数据集的**文档和问题都配套**
- 零样本指的是模型没在该数据集上fine-tune

---

### 3. 领域专用 RAG 的评测标准

[**DoRA: Domain-oriented RAG Assessment**](https://arxiv.org/html/2604.17943v1):
> "Domain-specific RAG evaluation requires **synthetic benchmarking from the target corpus**"

[**TRIAD: Domain-Specific RAG Evaluation**](https://arxiv.org/html/2608.21558):
> "Generate question–answer pairs **for the domain-specific knowledge base** of a RAG system"

**✅ 学术界明确：领域 RAG 必须用领域知识库生成测试问题**

## 🔍 为什么不是"数据泄露"？

### 原因 1: 检索器不"学习"文档内容

```
深度学习模型：
  训练阶段：model.parameters ← f(training_data)  # 参数被更新
  测试阶段：prediction = model(test_data)        # 如果 test_data 在训练集，直接记住答案
  ❌ 泄露：模型"记住"了测试样本

RAG 检索器：
  索引阶段：index ← embed(documents)             # 只是编码，不更新参数
  检索阶段：results = retrieve(query)            # 语义匹配，无法"记住"
  ✅ 无泄露：检索器无法预知哪个 query 对应哪个 document
```

### 原因 2: 评测的是"匹配能力"，不是"记忆能力"

| 任务 | 评测目标 | 泄露影响 |
|------|---------|---------|
| **分类任务** | 预测标签 | 如果见过测试样本，直接记住标签 ❌ |
| **检索任务** | 语义匹配 | 见过文档不代表能匹配到正确问题 ✅ |

**关键**：检索器评测的是"给定新问题，能否找到相关文档"的能力，而不是"记住问题-文档对"

---

### 原因 3: 测试集的"新"在于问题，不在于文档

**正确的训练-测试分离**（在 RAG 中）：

| 数据 | 训练阶段 | 测试阶段 | 备注 |
|------|---------|---------|------|
| **文档** | 建立索引 | 同样的文档 | ✅ 文档是固定的知识库 |
| **问题** | ❌ 未见过 | ✅ 新问题 | ✅ 测试集是新问题 |
| **相关性** | ❌ 未见过 | ✅ 新标注 | ✅ 评测能否找到正确文档 |

**类比**：
- 图书馆的书（文档）是固定的
- 读者的问题（query）是新的
- 评测图书管理员能否根据新问题找到正确的书

## 📊 学术界如何区分"In-Domain"和"Zero-Shot"？

### 情况 1: In-Domain Evaluation（我们的情况）
```
知识库：行人流领域 34 篇文献
问题：基于这 34 篇生成的 30 个问题
评测：检索器能否找到相关文献

✅ 合理：评测的是在已知知识库上的检索能力
```

### 情况 2: Zero-Shot Evaluation
```
知识库：通用维基百科
问题：医学、法律、编程等多个领域
评测：检索器在未见过领域的泛化能力

✅ 合理：评测的是跨域泛化能力
```

### 情况 3: Out-of-Distribution (真正的泄露风险)
```
训练：在 A 数据集上 fine-tune embedding 模型
测试：在 A 数据集上评测
❌ 有问题：模型可能过拟合 A 数据集的特征
```

## ⚠️ 什么时候才是"泄露"？

### 场景 A：Fine-tune Embedding 模型（有风险）

```python
# ❌ 有泄露风险的做法
train_pairs = [
    ("什么是基本图？", "T1-01"),  # 训练集
    ("楼梯疏散特征？", "T3-06"),
]

# Fine-tune BGE-M3
model.train(train_pairs)

# 测试
test_query = "什么是基本图？"  # ❌ 如果测试问题在训练集，有泄露
```

### 场景 B：只建索引不 Fine-tune（无风险）

```python
# ✅ 无泄露风险的做法（我们的方法）
# 只建索引，不训练
index = embed_documents(knowledge_base)

# 测试
test_query = "什么是基本图？"  # ✅ 新问题，检索器需要语义匹配
```

## 🔬 学术证据总结

### 1. [BEIR Benchmark](https://arxiv.org/html/2104.08663) (NeurIPS 2021)
> "文档集和问题集配套是标准做法，零样本指的是模型未在该任务上训练"

### 2. [TRIAD Framework](https://arxiv.org/html/2608.21558) (2026)
> "从领域知识库生成测试问题是评测领域 RAG 的标准方法"

### 3. [Stanford IR Book](https://nlp.stanford.edu/IR-book/pdf/08eval.pdf)
> "IR 评测需要固定文档集、查询集和相关性标注，三者配套"

### 4. [DoRA](https://arxiv.org/html/2604.17943v1) (2026)
> "通用基准无法评测领域 RAG，必须构建领域测试集"
